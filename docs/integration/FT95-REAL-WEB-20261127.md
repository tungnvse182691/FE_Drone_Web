Real tracker reads dataset identity, `GET /projects/{projectId}/ai-videos?datasetId=&offset=&limit=`, then `GET /processing-jobs/{jobId}`. It preserves workId/jobId separately and propagates errors; it does not read mock results or substitute a project job without dataset lineage.

Real detail URLs use `/pm/surveys/{taskId}?dataset={datasetId}&work={workId}&job={jobId}&det={detectionId}`. Detail reload reads dataset/task, candidate facts, disposition/decision and the linked defect. Dataset dataVersionId must match candidate datasetVersionId. FT95 candidate facts expose the work identity in their `runId` field; it is checked against the explicit URL workId, never used as a mock-run ID. A wrong scope fails instead of displaying another result.

KEEP_NEW takes routeVersionId from current candidate facts as the classification roadSectionVersionId, and compares current sourceVersion/geometryVersion with the candidate-match snapshot. Existing command journal, idempotency and decision receipt readback remain. KEEP_NEW/REJECT reread candidate state after the command; no automatic mutation replay was added.

Viewport uses the source video file content endpoint with Web cookies, seeks to timestampMs and drives its existing scrubber from media time/duration. The simulated playback timer is removed. Frame images remain available; bounding boxes are shown only near their detection timestamp.

## Backend blockers

- `GET /projects/{projectId}/ai-videos` returns 401 with a valid WebSession. Tracker displays the HTTP error rather than an empty or successful result. No Bearer workaround.
- There is no detection collection/pagination endpoint for a job. `/projects/{projectId}/candidates` is a matching lookup for one detectionId, not a job result collection. A known detection can be opened with an explicit partial-list warning; this does not claim to load the full set of detections. No seed JSON or SQL discovery is used by FE.
